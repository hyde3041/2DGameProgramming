# 궁수 공격: 같은 부품을 회전해 만드는 방식

**현재 적용하지 않는 실험 버전이다.** 2026-11-06 사용자가 이전 그림을 선호하여 [팔 두께 수정 버전](archer-arm-edit.md)으로 복원했다. 아래 자료와 제작기는 작업 이력으로 보존한다.

2026-11-06 사용자 승인에 따라 프레임별 상체 그림을 교체하던 방식에서 고정된 부위 원본을 움직이는 방식으로 변경했다. 궁수 공격의 모든 16장은 위팔·팔뚝·손·활의 동일한 PNG를 사용한다.

## 현행 파일

- 게임 시트: `game/asset/character/main/archer/<front|back|side>/attack-sheet.png`
- 부위 원본: `game/asset/character/icon/layers/archer/<방향>/attack/rigid/`
- [연결점·부위 경로·해시](archer-rigid-rig.json), [게임 시간·프레임 좌표](archer.json)
- [실제 시트 재생 미리보기](../../../game/asset/character/icon/preview/archer-attack-rigid.mp4)
- ZIP: `.build/deliverables/archer-attack-16frames-rigid.zip`

각 방향 폴더에 `bow-upper`, `pull-upper`, `bow-forearm`, `pull-forearm`, `bow-hand`, `pull-hand`가 하나씩 있다. 몸통과 발은 `base`, 가려진 면은 `under`, 머리와 묶은 머리는 `head`, `hair`이며 활은 `bow`다. 시트 프레임 번호에 따라 다른 팔 그림을 선택하는 코드는 없다. 손도 같은 그림을 계속 쓰므로 별도의 손가락 펴기 그림으로 교체하지 않는다.

## 연결과 크기

- 원본 팔 부위를 게임 크기로 준비할 때 한 번만 맞춘다. 위팔 관절 길이 17px, 팔뚝 19px, 손목에서 활·시위 접점까지 7px이다. PNG 전체 크기는 여유 공간을 포함한 64×64다.
- `archer-rigid-renderer.js`의 모든 부위는 이동과 회전만 사용한다. 매 프레임 확대·축소, 기울임 변형, 부위별 늘이기, 자세 그림 교체를 하지 않는다.
- 어깨→팔꿈치→손목→활 접점의 계층을 연결한다. 손이 관절의 도달 범위를 벗어나는 경우 손의 이동 경로를 도달 범위로 제한하며, 팔을 늘이지 않는다.
- 원래 머리·머리카락을 사용하며, 몸통의 남은 원본 색과 위치를 유지한다. 이전 팔과 무기에 가려져 있던 부분만 기존 분리 원본의 몸통·다리로 보완한다. 원본 발 아래 영역과 발 기준점 (160, 288)을 유지한다.
- 활은 기존 정면의 나무 그림에서 손에 가려졌던 손잡이만 보완한 고정 원본이다. 후면용 원본은 준비 단계에서 한 번 반전해 별도 PNG로 저장한다. 재생 중에는 활도 회전·이동만 한다. 시위는 끝점과 손의 위치로 그리며 발사 후 진동한다.
- 한 번 준비한 부위 PNG의 해시는 모든 프레임에서 같다. 회전 시 화면의 가로·세로 범위와 가장자리의 안티앨리어싱은 달라질 수 있으나 부위의 실제 배율과 관절 길이는 고정이다.

## 그림 준비

내장 **image_gen**으로 기존 캐릭터와 기존 상체를 참조해 정면·후면의 팔 부위 한 세트를 각각 만들었다. 별도의 애니메이션 자세 16장을 생성하지 않았다. 옆면은 정면 팔 부위와 같은 그림을 공유하며, 몸통·머리·연결점은 옆면 자료를 사용한다.

원본 아틀라스와 실제 잘라 쓴 부위가 `rigid/`에 함께 있다. [정면 프롬프트](archer-rigid-front-prompt.txt), [후면 프롬프트](archer-rigid-back-prompt.txt)를 보관한다. 기존 `source-v2/`, `arm-edit/`는 이전 제작 이력이며 현행 공격 재생성에 사용하지 않는다.

## 재생성

```text
node tools/prepare_archer_rigid.mjs
node tools/build_archer_attack.mjs
node tools/build_archer_attack.mjs --apply
python tools/export_attack_sheets.py archer
```

검사 출력은 `.build/archer-attack-rigid/`이다. 적용 전에 백업한다. `--apply`는 세 방향 시트와 재생 데이터·미리보기를 갱신한다. Python의 기존 `AttackSprite`, `load_image()`, `update(delta_time)`, `clip_draw()` 연결은 유지한다. 각 방향 16프레임·16FPS·1초, 07번 발사, 4열×4행의 1280×1280 RGBA 시트이며 프레임은 320×320이다.

공격 00번도 동일한 고정 부위를 조립한 준비 자세다. 기존 Idle 그림을 첫 장에 그대로 끼워 넣거나 프레임과 섞지 않는다. Idle 시트는 보존했으므로 공격 00번과 기존 Idle 00번이 픽셀 단위로 같지는 않다. 공격 완료 시 기존 Idle로 돌아간다.

## 확인한 결과

- 앞·뒤·옆 각각 위팔·팔뚝·손의 여섯 부위가 같은 파일로 16회씩 사용되는지 검사했다.
- 48개 프레임의 회전 행렬에서 배율·기울임 오차는 2.3×10⁻¹⁶ 이하, 관절 거리 오차는 4.0×10⁻¹⁴px 이하이다. 위팔·팔뚝·손 접점 길이는 17·19·7px로 유지된다.
- 모든 방향에서 16장이 서로 다르며, 투명 배경·규격·원래 발 아래 RGBA와 기준점을 확인했다. 회전 후 생기는 1~3px의 독립 잔여 조각을 정리했으며, 프레임에서 화살 외의 떠 있는 조각은 없었다.
- 기존 Python 단위 검사 10개 통과. 실제 pico2d/SDL에서 궁수·석궁병의 총 6방향을 재생해 각각 16장 출력과 기존 Idle 00 복귀, main의 선택·공격·종료를 확인했다.
- SHA-256으로 Idle 24개, 다른 공격 21개, 원본 이미지 104개와 궁수 기존 정렬 부위 120개 보존을 확인했다.
- 실제 시트 기반 MP4(1200×340, 약 6.2초)의 디코딩과 재생, ZIP의 PNG와 실제 게임 PNG 일치를 확인했다.
